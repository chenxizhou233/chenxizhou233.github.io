本来感觉没啥难的，半路杀出一个和 Prog1 一样恶心的语法，记录一下。

Formal Semantics

这里依然是取一个子集, 我们叫它 C0.

Tokens

两个函数

我们有两层抽象：

  1. 变量名到地址，用 ρ\rhoρ 表示
  2. 地址到储存的值，用 μ\muμ 表示

理论上来说， state Σ=ρ×μ\Sigma = \rho \times \muΣ=ρ×μ, 但有了语法糖我们直接写变量名到值的语法糖也行。

注意如果有 NULL 地址的话好像还是得分开写。

Config & Execution Trace

进一步，我们定义 Config ccc 为 Prog×ΣProg \times \SigmaProg×Σ

然后 Execution Trace 就是一个程序执行后 ccc 的集合。所以是：

⟨p∣σ⟩=c1c2c3… \langle p|\sigma \rangle =c_1c_2c_3\dots ⟨p∣σ⟩=c1​c2​c3​…

Eval

这里分为两种 Eval ： R and L

R 出 Val， L 出地址。

两个可以通过 μ\muμ 互转

Termination

到这里应该可以看出来这个是状态机模型了。

这里 Terminate 的定义是对于一个 Execution Trace c1,…,cnc1,\dots,c_nc1,…,cn​, 不存在 c′c'c′ 使得 cn→c′c_n\rightarrow c'cn​→c′, 那么有 ⟨p∣σ⟩↓cn\langle p|\sigma\rangle \downarrow c_n⟨p∣σ⟩↓cn​， 也即这个 Config terminate 于 cnc_ncn​. 反之就不 Terminate。

记住 R 出 Val， L 出 地址
